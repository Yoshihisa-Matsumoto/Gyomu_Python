# Gyomu Concept

[US English](README.md) | JP 日本語

## 概要

Gyomu Concept は、ソースコード分析と人間が管理するナレッジを橋渡しして構造化されたプロジェクトモデルを構築する Python パッケージです。その主な目的は、プロジェクトのアーキテクチャ、責務、設計意図、運用の知見を、人間と AI の双方が活用できる統一されたモデルとして表現することです。 

このパッケージは、標準的なドキュメントツールとして機能するのではなく、プロジェクトのナレッジを構造化して、README ファイルや LLM コンテキストを含む包括的なドキュメントを自動生成します。自動分析と、モジュール化されたドキュメント定義およびセクションビルダーを組み合わせることで、複雑なプロジェクトアーキテクチャを理解し伝達するための揺るぎない基盤を提供します。

## アーキテクチャ

このパッケージは、ドキュメント生成、LLMコンテキスト構築、構造解析に責任を分割するモジュール式のコンポーネントで構成されています。documentサブパッケージは、設定可能なドキュメント定義とファイルパスのResolverを使用して、出力レンダリング、翻訳、コンテキスト初期化、非同期セクション構築を調整します。 

特化型のLLMコンテキストを構築するために、専用のセクションビルダーが、アーキテクチャ、設計意図、ナビゲーション、パッケージの役割といった特定のコンポーネントを組み立てます。基盤となる構造解析はdirectoryおよびpackageサブパッケージによって処理され、階層的なディレクトリのConcept、ファイルサマリーレコード、パッケージ依存関係の構築、処理、読み込み、永続化、管理を連携して行います。

## インストール

uv を使用してインストールします。

```bash
uv add gyomu-concept
```

## 依存関係

このパッケージは、動作するためにいくつかのランタイム依存関係を利用します。成功、失敗、および Result 型を用いた明示的な成功・失敗の表現のために `returns` パッケージを使用しています。さらに、スキーマと共通型のために `gyomu-schema`、I/O などの一般的なインフラストラクチャ処理のために `gyomu-infra`、README および Concept 作成時の LLM 処理のために `gyomu-ai-compiler` を統合しています。

## 開発

コントリビューターは、構造化された知識モデルと最終的なドキュメント表現との間の分離を厳格に維持する必要があります。Conceptは、アーキテクチャ、責務、設計意図、運用知識を表す抽象的な知識モデルとして機能するため、その内部スキーマは特定のドキュメント形式、出力言語、表現スタイルから独立している必要があります。ソースコード分析、Concept構築、ドキュメント生成は、完全に独立した関心事として動作します。ドキュメント生成では、モデル自体にフォーマットロジックを埋め込むのではなく、専用の出力レンダラーやファイルパスResolverを介して、Conceptおよび人間が管理する知識を入力データとして扱い、フォーマット固有の構造へと変換する必要があります。

人工知能が関与するすべてのやり取りは、外部のAIプロバイダーや特定のモデルとの直接的な結合を防ぐために、`gyomu-ai-compiler`経由で厳格にルーティングする必要があります。実行メカニズムは抽象化されていますが、コンテンツの翻訳戦略などのドキュメント固有の定義は、Conceptの設定内で直接表現する必要があります。さらに、コントリビューターは、パッケージConceptやディレクトリConceptなど、異なる粒度のConceptをそれぞれの異なるスコープに従って管理し、階層的なプロジェクトモデルが自動化されたソースコード分析と人間がキュレーションした知識を正確に統合できるようにする必要があります。

## Public API

- ドキュメント生成とレンダリング - プロジェクトドキュメント作成のための構造化されたドキュメント生成、レンダリング、翻訳、コンテキスト初期化を管理します。
- LLMコンテキスト構成 - LLMコンテキストを構築するために、アーキテクチャ、設計原則、ガイドラインなどの専門的なセクションを構成します。
- ディレクトリConceptの管理 - 階層的なディレクトリConceptおよびファイルサマリーレコードの構築、読み込み、処理、永続化を行います。
- パッケージConceptの操作 - パッケージレベルのConcept、依存関係の収集、パス解決、永続化操作を処理します。
