# Gyomu Workflow

[US English](README.md) | JP 日本語

## 概要

このパッケージは Gyomu CLI のスナップショットワークフローエンジンを駆動し、コード解析、Concept 生成、ドキュメント生成を統合パイプラインとして実行するためのオーケストレーション基盤を提供します。主な目的は、実行順序の管理とチェックポイントによる成果物の状態監視を行い、プロセスの再開やインクリメンタルな更新を可能にすることです。個別の処理ロジックを全体的なワークフロー制御から分離することで、再現性と保守性の高いプロジェクト運用を実現します。実行パイプライン、チェックポイント管理、対象ファイルの解決、プロジェクト構造の検証を処理し、一貫した実行を保証します。

## アーキテクチャ

`gyomu-workflow` パッケージは、Gyomu CLI のワークフローエンジンを駆動するコアスナップショットモジュールを中心に構成されています。責務は、ワークフローのオーケストレーション、状態の永続化、ターゲットの解決、および検証を処理する個別のコンポーネントに分割されています。

トップレベルの `src/gyomu_workflow` パッケージがスナップショットワークフロー全体を調整し、ネストされた `snapshot` ディレクトリには実行と検証のための具体的なメカニズムが格納されています。これらのコンポーネントが連携して、パイプラインステップの実行、ターゲットファイルに対するアクションの実行、状態追跡のためのチェックポイントの管理、設定スキーマおよびパッケージ構造ルールの適用を行います。

## インストール

uv を使用してインストールします。

```bash
uv add gyomu-workflow
```

## 依存関係

このパッケージはPydanticバージョン2.xの互換性を対象に設計されています。ランタイム依存関係には、スキーマ定義、データ検証、およびシリアル化や逆シリアル化を行う `pydantic` が含まれます。また、スキーマと共通型用の `gyomu-schema`、I/Oなどの汎用インフラストラクチャ処理用の `gyomu-infra`、Pythonパッケージおよびファイル分析用の `gyomu-python-analysis`、Pythonファイルのdocstring更新用の `gyomu-docstring`、そしてディレクトリのConcept、パッケージのConcept、およびREADME.mdファイル作成用の `gyomu-concept` に依存しています。

## 開発

コントリビューターは、ワークフローオーケストレーションと下位のタスク実装の間で厳密な分離を徹底する必要があります。ワークフローエンジンは実行順序、ステップの条件、状態遷移を管理しますが、実装詳細に依存するのではなく、定義されたインターフェースを介して、スナップショットや変更検知などの専門的なタスクをそれぞれの専用パッケージに委譲する必要があります。さらに、オーケストレーション層はCLIやMCPなどの配信メカニズムから完全に独立している必要があり、ワークフローロジックが再利用可能であり続け、外部インターフェースから切り離されることを保証します。

再現可能で保守性の高いプロジェクト処理を保証するために、状態管理システムは物理的な成果物の存在とは独立して、ステップの成功した実行を記録するチェックポイントに依存します。必要な成果物が欠落している場合、チェックポイントが完了としてマークしている場合でも、ワークフローは必要なステップを再実行する必要があります。コントリビューターは、成功と失敗を明示的に処理する独立したアクションとしてステップを実装し、ステップの失敗時にただちに実行を停止し、現在のチェックポイントと成果物の状態に基づいて必要なステップのみを実行する必要があります。

## Public API

- Workflow Orchestration - スナップショットワークフローの実行をオーケストレーションし、パイプラインのステップを調整し、リクエストパラメータを検証し、ターゲットファイルに対してアクションを実行します。
- Checkpoint Management - スナップショットの状態、チェックポイントを通じた永続化、およびワークフロー実行全体にわたる履歴の追跡を管理します。
- Target Resolution and Filtering - スナップショット実行のターゲットファイルとディレクトリを解決し、ファイルフィルターとパターンマッチングを適用します。
- Configuration and Validation - スナップショットの実行とPythonパッケージの構造に関するコアデータモデル、リクエスト設定、および検証ルールを定義します。
