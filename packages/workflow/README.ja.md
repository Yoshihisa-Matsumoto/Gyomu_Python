# Gyomu Workflow

[US English](README.md) | JP 日本語

## 概要

gyomu-workflow パッケージは Gyomu CLI 向けの中核的なオーケストレーションエンジンを提供し、コード分析、concept 生成、ドキュメント処理の一貫したワークフローを確立します。その主な目的は、チェックポイントを通じて実行順序と状態を管理し、必要なタスクのみを実行してスムーズな再開とインクリメンタルな更新を可能にすることです。 

個別の処理の実装を全体のワークフロー制御から分離することで、プロジェクトの操作に向けて再現性と保守性に優れた実行環境を提供します。複雑な開発タスクを効率的に合理化するため、スナップショットの実行、リクエストの検証、ターゲットの解決、および特殊なパイプラインアクションを処理します。

## アーキテクチャ

このパッケージは、責務を明確な操作レイヤーに分割するコアワークフローオーケストレーションエンジンを中心に構成されています。ルートパッケージレベルでは、コンポーネントがスナップショット実行、リクエスト検証、ターゲットのResolver、チェックポイントを通じたインクリメンタル処理を処理します。

責務は、パイプラインを実行するために連携する特化した内部モジュールによってさらに構造化されています。専用のスナップショットコンポーネントが、ワークフローの実行管理、パイプラインの状態追跡、Pythonパッケージ構造の検証を行います。
,
これらのコンポーネントは、ワークフローランナーがスナップショットの実行、アクションの設定、チェックポイントの管理を調整するパイプラインアーキテクチャ内で相互作用します。これらが一体となって、ディレクトリ生成、docstringの更新、LLMコンテキスト生成、パッケージ処理、README作成などの特化したタスクを駆動します。

## インストール

uv を使用してインストールします。

```bash
uv add gyomu-workflow
```

## 依存関係

本パッケージは Pydantic バージョン 2.x との互換性を考慮して設計されています。

ランタイム操作においては、スキーマ定義、データ検証、シリアル化を行う pydantic や、共有スキーマと型の gyomu-schema、入出力およびベースライン処理の gyomu-infra、Python パッケージおよびファイル分析の gyomu-python-analysis、docstring 更新の gyomu-docstring、ディレクトリとパッケージの Concept および README.md ファイル作成の gyomu-concept をはじめとする複数のパッケージに依存しています。

## 開発

コントリビューターは、ワークフローの実行順序のオーケストレーションと、個々の処理アクションの具体的な実装を厳密に分離しなければなりません。ワークフローは、低レベルの処理詳細を直接扱わずにステップのシーケンスと実行条件を管理し、スナップショット管理や変更検知などのタスクを直接の依存関係ではなく定義されたインターフェースを介して専用の下流パッケージに委譲する必要があります。すべてのワークフローステップは独立したアクションとして扱われるべきであり、オーケストレーション層の再利用性を維持するため、アーキテクチャはCLIやMCPなどの具体的な利用インターフェースから完全に疎結合である必要があります。

状態管理は、チェックポイントと成果物の存在の間の明確な境界に依存します。チェックポイントは過去の正常なステップ実行の履歴レコードとして厳密に扱われる必要があり、現在生成されている成果物の物理的な存在とは完全に分離されます。成果物が欠落している場合、対応するチェックポイントが完了を示している場合であっても、システムは必要な処理を再実行しなければなりません。さらに、実行エンジンはステップの成功と失敗を明示的に処理し、障害発生後に後続のステップが実行されないよう、即座に実行を停止する必要があります。

## Public API

- ワークフローパイプラインとチェックポイント - ワークフローの実行ステップをオーケストレーションし、増分処理のためのチェックポイントを管理し、パイプラインの状態を追跡します。
- リクエストの検証とターゲットの解決 - ターゲットファイルを解決し、スナップショットのリクエストを検証し、Pythonパッケージの構造を確認します。
- 特殊なパイプラインアクション - ディレクトリの生成、docstringの更新、LLMコンテキストの生成、READMEの作成など、特殊なパイプラインタスクを実行します。
