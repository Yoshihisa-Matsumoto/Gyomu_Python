# Gyomu Workflow

[US English](README.md) | JP 日本語

## 概要

`gyomu-workflow` は Gyomu CLI のコアワークフローエンジンとして機能し、コード解析、Concept 生成、ドキュメント生成のプロセスを統合されたパイプラインとして実行するためのオーケストレーション基盤を提供します。その主な目的は、実行順序の管理、チェックポイントや成果物の状態の追跡を行い、スムーズな再開とインクリメンタルな更新を可能にするために必要なタスクのみが実行されるようにすることです。 

個々のタスクの実装をワークフロー全体の制御から分離することで、このパッケージは再現性と保守性の高いプロジェクト環境を構築します。リクエストの変換、検証、チェックポイントの追跡、ターゲットの Resolver、特殊なプロジェクトアクションを調整することで、スナップショットパイプラインを駆動します。

## アーキテクチャ

このパッケージは、リクエストの処理と実行を駆動するコアとなるスナップショットワークフローパイプラインを中心に構成されています。責務は、リクエストの検証、状態の追跡、ターゲットのResolver、およびアクションの実行を処理する個別の協調コンポーネントに分割されています。

アーキテクチャはスナップショットモジュールを中心に据えており、これが主要な実行ランナーとして機能します。ユーザーのリクエストとパッケージ構造を最初に翻訳および検証することで、ワークフローを調整します。その後、永続的なチェックポイントと入力フィンガープリントを通じてパイプラインの状態とステップの完了を追跡しつつ、ターゲットソースファイルのResolverとフィルタリングを行います。

ターゲットと状態が検証されると、ランナーは、docstring、README、パッケージ、LLMコンテキストの生成などの特殊なプロジェクトアクションの実行を委譲し、モジュール化された構造化されたワークフローパイプラインを確保します。

## インストール

uv を使用してインストールします。

```bash
uv add gyomu-workflow
```

## 依存関係

このパッケージは、スキーマ定義、データ検証、シリアライゼーションのために Pydantic バージョン 2.x を必要とします。

さらに、共通の型とスキーマ用の gyomu-schema、入出力および一般的なインフラストラクチャ処理用の gyomu-infra、ファイルとパッケージの解析用の gyomu-python-analysis、docstring 更新用の gyomu-docstring、ディレクトリとパッケージの Concept ならびに README.md ファイル生成用の gyomu-concept を含む、いくつかのランタイム依存関係に依存しています。

## 開発

コントリビューターは、ワークフローの実行順序と、個々の処理ステップの詳細な実装を厳格に分離しなければなりません。すべてのワークフローステップは独立したActionとして扱われなければならず、ワークフローエンジンは順序付けと実行条件のみを管理し、スナップショットや変更検知などの具体的なドメインタスクは、定義されたインターフェースを介して専用の下位パッケージに委譲されるようにします。さらに、パッケージはCLIやMCPなどの実行インターフェースに対して非依存（agnostic）を維持し、すべての処理ロジックが再利用可能であり、特定のユーザーインタラクション層から切り離されていることを保証する必要があります。

状態管理は、ステップの完了を追跡するために永続的なチェックポイントと入力フィンガープリンティングに依存しますが、チェックポイントは、現在の成果物の存在を代理するものではなく、過去の成功の履歴記録として厳格に扱われなければなりません。必要な生成物である成果物が欠落している場合は、チェックポイントで完了とマークされている場合でも、対応するステップを再実行する必要があり、これによりインクリメンタルな更新と回復力のあるワークフローの再開をサポートします。コントリビューターは、予測可能なパイプラインの復旧を維持するために、履歴の状態追跡と物理的な成果物の検証との間のこの分離を維持しなければなりません。

パイプラインの実行はフェイルファストの原則に従う必要があり、各ステップの成功と失敗が明示的に処理され、ステップが失敗した後の下流での実行を防ぎます。コントリビューターは、ワークフロー層から下位パッケージの実装詳細への直接的な依存関係を持ち込むことを厳しく禁じられています。ドメイン固有のロジックとのすべてのインタラクションは、確立されたインターフェースを厳格に経由する必要があり、再現可能、保守可能、およびモジュール化されたプロジェクト処理に必要な境界を維持します。

## Public API

- リクエストの検証と変換 - プロジェクトスナップショットを生成するためのユーザリクエストと構造的要件の変換および検証を行います。
- チェックポイントと状態追跡 - チェックポイントと入力フィンガープリントを使用して、実行の進捗、ファイルの変更、およびステップの完了を追跡します。
- ターゲットの解決とフィルタリング - スナップショットのターゲットを解決し、指定されたパスパターンの条件に従ってプロジェクトファイルをフィルタリングします。
- ワークフローアクションの実行 - ドキュメント文字列の処理、パッケージ分析、READMEの生成、LLMコンテキストの作成などのモジュール化されたワークフローアクションを実行します。
