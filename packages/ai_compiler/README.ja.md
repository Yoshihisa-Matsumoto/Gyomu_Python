# Gyomu AI Compiler

[US English](README.md) | JP 日本語

## 概要

このパッケージは、Gyomuプロジェクト向けに設計されたAI処理のコンパイルおよび実行基盤を提供します。その目的は、AI処理の定義やコンテキストを、ルート、プロンプト、実行戦略、検証ルールなどの構造化されたコンポーネントに変換し、gyomu-aiを通じて一貫して実行することです。 

専門的なAIオーケストレーションおよびコンパイルツールキットとして、このパッケージは、ドキュメント生成、docstringの更新、パッケージ分析、およびドキュメント翻訳を自動化します。コードインテリジェンス操作向けに調整された、コンテキストモデリング、プロンプトレンダリング、実行エンジン、決定的スキーマ定義を含むモジュール式パイプラインアーキテクチャを確立します。

## アーキテクチャ

`gyomu-ai-compiler` パッケージは、AI を活用したオーケストレーション、ドキュメント生成、翻訳処理の各機能に責務を分割する、モジュール式パイプラインアーキテクチャを中心に構成されています。

コア機能は特化型パイプラインに構造化されています。docstring 更新パイプラインは、専用のスキーマコンポーネントと連携して決定論的な更新プラン、アクション、値を定義し、コンテキストモジュールはファイル状態やコード宣言をモデル化します。同時に、レンダリングコンポーネントは LLM の会話メッセージ、プロンプト、ユーザーデータ構造を構築し、アーキテクチャ概要、設計意図、README の内容などのドキュメントセクションを生成します。

実行における責務は特化型エンジンによって処理されます。例えば、翻訳実行コンポーネントは、リトライ機構、一時的な状態追跡、検証用フォーマットとともに、ドキュメントコンテンツの翻訳を管理します。これらの連携するコンポーネントは、自動化されたコードインテリジェンスとドキュメントのワークフローをサポートするため、コンテキストのモデル化、プロンプトのレンダリング、実行、スキーマ定義をそれぞれ分離します。

## インストール

uv を使用してインストールします。

```bash
uv add gyomu-ai-compiler
```

## 依存関係

このパッケージは、動作のためにいくつかのランタイム依存関係に依存しています。成功、失敗、および Result を用いた明示的な成功と失敗の表現には `returns` パッケージを使用します。さらに、スキーマと共通型のために `gyomu-schema`、I/O などの汎用的なインフラストラクチャ処理のために `gyomu-infra`、LLM 処理のために `gyomu-ai` を統合しています。

## 開発

コントリューターは、AIモデルやプロバイダーに直接アクセスするのではなく、すべてのAI処理が必ず `gyomu-ai` の実行メカニズムに依存するようにしなければなりません。この関心の分離により、AIタスクは明示的な Route を通じてのみ識別され、下位のモデル設定とAI処理の実コンテンツが効果的に切り離されます。さらに、AIとのすべてのインタラクションは、必要な実行コンテキストを明確に構造化した明示的な Prompt として組み立てる必要があります。信頼性を担保するため、すべてのAI出力は使用前に定義された Schema および Validator を経由する必要があり、実行失敗は失敗の原因や特定の実行フェーズなどの診断詳細を保持する構造化された Error として処理されなければなりません。一方、実行のリトライは定義された Retry 戦略によって厳密に制御されます。

AI処理に必要なすべての変換、翻訳、およびアセンブリは完全に Compiler 側で行う必要があり、実行フローへのプロバイダー固有ロジックの導入は禁止されています。Pipeline は、上位パッケージからコンテキストと定義を受け取り、それらを Route、Prompt、実行戦略、検証レイヤーなどの標準化された操作要素に変換する、再利用可能なコンポーネントとして目的を持って設計されなければなりません。コントリューターには、これらのアーキテクチャ境界を厳格に維持し、実行戦略、検証、プロバイダーアクセスが明確に分離された、決定論的で疎結合な設計がコードベース全体で維持されるようにすることが求められます。

## Public API

- Docstring Management Schemas - AIを活用した決定的なドキュメンテーション文字列の生成とコード更新に向けた、構造化スキーマ、置換処理、実行計画を定義します。
- LLM Context Rendering - アーキテクチャの概要、制約、設計セクションを生成するための、会話メッセージ、プロンプト、コンテキスト構造を構築します。
- README Generation Pipelines - 包括的なREADMEドキュメントセクションを作成するための、プロンプト、データ構造、メッセージフローを構築します。
- Translation Execution Engine - リトライ機構、一時的な状態追跡、検証フォーマットを組み込んだドキュメント翻訳タスクを実行します。
- Code Declaration Contexts - コード分析およびドキュメンテーション文字列パイプラインをサポートするための、宣言コンテキスト、ファイル状態、リトライオプションをモデル化します。
