# Gyomu Schema

[US English](README.md) | JP 日本語

## 概要

このパッケージは、Gyomuエコシステム向けの正規データモデル、検証ルール、スキーマを提供します。主な目的は、Python分析、Concept、ドキュメント、知識、スナップショットなどの機能間でデータコントラクトを確立する、共有スキーマ、型定義、エラー型、プロトコル、および汎用ユーティリティを定義することです。

これらの基盤となるコントラクトを定義することで、パッケージ間の依存関係を疎結合に保ちながら、エコシステム全体で型安全性とデータの整合性を維持します。

## アーキテクチャ

このパッケージは、Gyomuエコシステムを支えるドメイン特化型データモデルと検証ルールの集約されたコレクションを中心に構成されています。責務は、Pythonコードの解析、構造化ドキュメント、エラー管理、知識表現を処理する専門モジュールに分割されており、その基盤となるユーティリティおよびシリアライゼーションフレームワークによって支えられています。

コード解析は、PythonのAST式、文、型構造、およびクラス、関数、モジュール、依存関係といった高レベルのコード構造をモデル化する専用コンポーネントに整理されています。同時に、ドキュメントおよび知識管理コンポーネントは、コンテンツ要素、ガイドライン、技術リファレンス、運用ロードマップに対して、構造化定義、検証ルール、翻訳設定を提供します。

標準化されたドメインエラー処理がこれらのレイヤー全体を横断し、AI、設定、データベース、I/O、検証の各タスクに向けて、基本エラークラス、運用フェーズ、解決戦略を提供します。これらの連携するコンポーネントにより、すべてのアプリケーション操作において一貫したスキーマの適用、シリアライゼーション、検証が保証されます。

## インストール

uv を使用してインストールします。

```bash
uv add gyomu-schema
```

## 依存関係

このパッケージは、スキーマ定義、データ検証、シリアライゼーション、およびデシリアライゼーションに必須となるPydanticバージョン2.x向けに設計されています。ランタイムでの使用において、このパッケージはPydanticに依存し、Success、Failure、Resultを使用して成功と失敗を明示的に表現するためにreturnsを利用します。

## 開発

コントリビューターは、パッケージ間の関係性を疎結合に保つため、このパッケージがGyomuエコシステムの独立した共有基盤であり続け、他のGyomuパッケージに対する依存関係を一切持たないようにしなければなりません。Python Analysis、Concept、Document、Knowledge、Snapshotなどの機能間におけるデータコントラクトを規定するすべての標準データスキーマは、特にJSON、永続化層、MCPなどの外部境界でデータを処理する場合、Pydanticスキーマとして定義する必要があります。内部処理に限定される実装詳細は、Pydanticスキーマとして公開すべきではありません。値の混同を防ぎ、型安全性を強制するため、コントリビューターはID、パス、および意味を持つ値を表す際に、可能な限り型を使用する必要があります。さらに、Pydanticスキーマのアノテーションは、AIコード生成、ドキュメント生成、ナレッジ生成を支援するというランタイムの型情報にとどまらない重要な役割を果たすため、決して省略してはなりません。

アーキテクチャ上の境界として、Protocolsは具体的な実装を一切持たず、共有インターフェースコントラクトのみを定義することが求められます。一方、ユーティリティは汎用的であるべきであり、特定のGyomuのビジネスロジックを含めてはなりません。エラー処理は、アプリケーション層全体で一貫したエラー処理を保証するために、標準化されたエラー構造に準拠する必要があり、すべてのAPIは可能な限り不変かつ宣言的に設計されなければなりません。コードベースを改良する際、コントリビューターはGyomuエコシステム全体にわたってデータの整合性、型安全性、およびアーキテクチャの整合性を維持するために、これらの具体的な設計上の決定事項と制約を遵守することが求められます。

## Public API

- Python Code Analysis Schemas - Pythonのコード構造、AST式、文、型、モジュール解析を表現するための包括的なデータモデル。
- Document and Translation Schemas - 構造化文書、セクション、コンテンツ要素のためのスキーマ、バリデーションルール、および翻訳戦略。
- Error Handling and Recovery Schemas - アプリケーション操作のためのコアとなるドメイン固有のエラー処理クラス、解決戦略、およびリトライポリシー。
- Knowledge Management Schemas - 開発者向けの運用知識、コーディングガイドライン、ロードマップ、技術リファレンスを表現するためのスキーマ。
- Utility and Serialization Framework - シリアライゼーション、バリデーション、実行タイミング、および非同期/同期の実行結果ユーティリティ。
