# Gyomu AI

[US English](README.md) | JP 日本語

## 概要

このパッケージは、Gyomuプロジェクト向けの堅牢なAI実行フレームワークであり、人工知能統合のための統一されたインフラストラクチャを提供するように設計されています。主な目的は、さまざまなAIプロバイダーやSDKの差異を吸収し、利用側のパッケージを特定のサードパーティ製実装から切り離すことです。\n\n主にPydantic AIをベースに構築されたこのフレームワークは、ランタイム実行、モデルルーティング、エラー管理のための標準化されたアプローチを確立します。プロバイダー固有の構造を、一貫性のある生成、ストリーミング、および埋め込みの結果へとシームレスにマッピングすることにより、システム全体で信頼性の高い一貫したAIオペレーションを保証します。

## アーキテクチャ

このパッケージは、プロバイダ統合、実行管理、ツール処理、エラー管理、モデル表現に責任を分割する、協調動作するコンポーネントで構成されています。

プロバイダ統合レイヤーは、Pydantic AIのモデル、エージェント、ツール、プロンプト、結果を標準的な内部形式にマッピングします。このレイヤーは、アプリケーション全体で使用されるAIモデルの中核的なデータ構造と識別キーを定義する、モデル表現コンポーネントと密接に連携します。

実行環境は、テキスト生成、ストリーミング、オブジェクト生成、埋め込みなどの操作におけるランタイムコンテキスト、パラメータ、設定ポリシー、オブザーバ、結果構造を管理します。実行パラメータの設定とコンテキストはモデルの呼び出しと追跡をサポートし、実行結果は出力、メタデータ、トークン使用量をキャプチャします。

AIツールの実行、設定、結果に関するドメインロジックは個別にカプセル化され、専用のエラーハンドリングモジュールと連携して動作します。アプリケーション固有のエラー型と例外が、ルーティング操作とパブリックなツールのエラーハンドリングを管理し、フレームワーク全体で堅牢な実行を保証します。

## インストール

uv を使用してインストールします。

```bash
uv add gyomu-ai
```

## 依存関係

このプロジェクトはPydantic AI Version 2をベースに設計されているため、Pydantic AIのバージョン2.xが必要です。\n\nランタイム依存関係として、LLM処理にはPydantic AI、Success、Failure、Result型を用いた明示的な成功・失敗処理には `returns`、スキーマと共通型には `gyomu-schema`、I/Oなどの汎用的なインフラ処理には `gyomu-infra` をそれぞれ使用します。

## 開発

コントリビューターは、AIプロバイダー固有のSDKの抽象化を厳格に維持し、利用側のパッケージが外部プロバイダーに直接依存するのではなく、Gyomuの統一されたインターフェイスを介してのみ処理を行うようにしなければならない。モデルの選択と実行パスに対する一元的な制御を維持するため、すべてのAIリクエストの実行は、定義されたルーティング機構のみを経由してルーティングされなければならない。アーキテクチャの変更にあたっては、一時的な実行失敗に対処するために定義されたリトライ戦略の適用を必ず維持し、利用可能な場合はいつでもトラフィックを代替の実行経路に切り替えるフォールバック機構をシームレスに利用できるようにする必要がある。

エラーハンドリングの設計では、すべてのAI実行の失敗を、失敗の原因や実行フェーズなどの重要な診断情報を保持できる構造化エラーとして扱うことが求められる。コントリビューターは、プロバイダー固有の出力を、Gyomu固有の標準的かつ統一された結果構造に変換することが厳しく義務付けられている。コードを追加する際は、モデルレジストリ、エージェントの実行、コンテキスト管理、およびツールの設定が下位のSDKの細部から確実に切り離された状態に保たれるよう、これらの境界を厳守しなければならない。

## Public API

- Pydantic AI Integration - Pydantic AI のモデル、エージェント、ツール、プロンプト、結果を標準的な内部形式にマッピングする統合レイヤーです。
- Execution Environment - AI 操作の実行コンテキスト、ランタイムパラメータ、設定ポリシー、オブザーバー、結果構造の管理です。
- AI Tool Execution - AI ツールの実行、設定、およびパブリックエラーハンドリングに関するコアなドメインロジックと定義です。
- Error Handling and Routing - ルーティング操作におけるアプリケーション固有のエラー型と例外処理です。
- Model Representation - アプリケーション全体における AI モデルのコアデータ構造と識別キーです。
