# Gyomu Docstring

[US English](README.md) | JP 日本語

## 概要

このパッケージは、Pythonのソースコードのdocstringを管理するためのコアインフラストラクチャとして機能します。主な目的は、ソースファイル内のドキュメントの生成、更新、マージ、検証を自動化し、高い保守性と再現性を確保することです。

このパッケージは、docstringを解析して構造化されたドキュメント情報として扱い、更新内容を明確なプランとして表現します。分析、更新プランの策定、変更の適用の各プロセスを明確に分離することで、検証済みの変更をソースコードへ安全に反映させることができます。

## アーキテクチャ

このパッケージは、docstringの生成、マージ、および検証のエンドツーエンドのライフサイクルを調整するコアのupdateモジュールを中心に構成されています。責務は、コンテキスト分析、プランニング、レンダリング、および検証を処理する専門のコンポーネントに分割されています。

コンテキスト分析は宣言とファイルのターゲットを構築し、そのデータをプランニングコンポーネントに渡します。プランニングコンポーネントは、シンボルの更新、競合解決のマージ、およびリトライロジックを管理します。専用のレンダリングエンジンは、仕様に従ってdocstringのセクション、行、およびタグをフォーマットし、一方、実行および検証コンポーネントはソースファイルに更新を適用し、外部のフォーマッタやリンターを使用してそれらを検証します。

これらの処理フローをサポートするため、専用のエラー管理コンポーネントがカスタム例外型を定義し、パッケージ全体で更新の失敗を適切に処理します。

## インストール

uv を使用してインストールします。

```bash
uv add gyomu-docstring
```

## 依存関係

このパッケージは、動作のためにいくつかのランタイム依存関係を利用します。`returns` パッケージは、Success、Failure、Result 型による成功と失敗の明示的な表現に使用されます。さらに、`gyomu-schema` はスキーマと共通型のリポジトリとして機能し、`gyomu-infra` は入出力などの一般的なインフラストラクチャ処理を処理し、`gyomu-ai-compiler` は README および Concept の作成時の LLM 処理に使用されます。

## 開発

コントリビューターは、ドキュメントの計画、AIによるコンテンツ生成、およびコード修正の間で、厳格なアーキテクチャ上の分離を維持しなければなりません。ソースコードの構造解析が、ドキュメントのセクション、行、タグのレンダリングやフォーマット方法から独立していることを保証するため、ドキュメント文字列の解析とドキュメント生成は非結合の状態を維持する必要があります。さらに、AIによるコンテンツ生成は、コアとなるドキュメント文字列の管理ロジックから完全に隔離されなければならず、自動生成プロセスが管理エンジン内の組み込みルーチンではなく、厳格に上流の入力として機能することを保証します。

すべての更新操作は、明示的な中間表現によって制御されなければならず、宣言に対する要求された変更は、実行前にUpdate Planとして表現されます。ファイル操作は、すべての実行環境にわたるベースラインとして正規化されたパスモデルのみを使用し、モノレポ構造内での一貫したドキュメント更新動作を保証する必要があります。コード修正は検証可能な成果物として扱われなければならず、変更が元のPythonファイルに安全に適用される前に、更新されたコードソースの検証が必要となります。

## Public API

- Docstring Context Analysis - ドキュメント化可能なコードの対象や依存関係を特定するために、ファイルや宣言のコンテキストを構築します。
- Update and Merge Planning - ドキュメント文字列の更新やコンフリクト解決のマージを計画、構築、再試行します。
- Docstring Rendering Engine - 仕様に従ってドキュメント文字列の行、タグ、文字列をフォーマットしてレンダリングします。
- Execution and Validation - ファイルの更新を実行し、フォーマットおよびリンティングツールを使用して結果のコードを検証します。
- Error Management - ドキュメント文字列の更新失敗に対する専用のエラー型と処理を定義します。
