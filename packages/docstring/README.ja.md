# Gyomu Docstring

[US English](README.md) | JP 日本語

## 概要

このパッケージは、コードドキュメントの生成、更新、マージ、フォーマットを自動化するために設計された、包括的なdocstring管理基盤を提供します。主な目的は、ソースコードのコンテキストを分析してドキュメント情報を構造化し、更新を個別のプランとして表現した上で、検証済みの変更をソースに安全に適用することです。

分析、更新プランの作成、変更の適用を明確に分離することで、このパッケージは再現性と保守性に優れたコードドキュメントのワークフローを実現します。また、生成されたコードが既存の品質およびlint基準を満たしていることを確認するための検証メカニズムも組み込まれています。

## アーキテクチャ

gyomu-docstring パッケージは、自動 docstring 生成、更新、マージのエンドツーエンドのライフサイクルを管理する、連携するコンポーネントのコアセットを中心に構成されています。責務は、ソースコンテキストの分析、ドキュメントの計画、構造モデリング、フォーマット、品質管理を処理する専門のモジュールに分割されています。

パッケージは専用のディレクトリを使用して関心を分離します。コア更新レイヤーは、ファイル変更およびマージの作成、実行、レンダリング、検証を監督し、内部ユーティリティに依存してファイルコンテキストの構築、更新およびマージ計画の策定、フォーマットされた文字列のレンダリング、シグネチャの検証を行います。別の構造レイヤーは、docstring の基となる行、セクション、レンダリングされたシンボルをモデル化します。さらに、専用のエラー処理コンポーネントが、フェーズを認識する例外型とカスタム定義を提供し、更新の失敗を管理します。

## インストール

uv を使用してインストールします。

```bash
uv add gyomu-docstring
```

## 依存関係

ランタイム依存関係として、このパッケージは `returns` を利用して Success、Failure、Result による明示的な成功と失敗の表現を行います。さらに、スキーマと共通型には `gyomu-schema`、I/O などの一般的なインフラストラクチャ処理には `gyomu-infra`、README および Concept ファイルの作成時の LLM 処理には `gyomu-ai-compiler` を使用します。

## 開発

コントリビューターは、ドキュメント生成、docstringのパース、更新計画、ソースコード適用間のアーキテクチャ上の分離を厳格に維持する必要があります。docstringはソースコードの構造に対応する直接的な成果物として管理され、モノレポ環境全体で一貫した処理を保証するため、ファイル操作は正規化されたパスモデルに対してのみ実行される必要があります。AI駆動型のドキュメントコンテンツ生成は、docstringの機械的な管理およびパースから完全に切り離されていなければならず、更新が結合された副作用ではなく、独立した再現可能な処理として扱われることを保証します。

docstringに対するすべての変更は、適用前にUpdate Planとして明示的に表現され、対象のシグネチャ、変更されたソースコード、および更新計画が厳密な検証を受けられるようにする必要があります。コントリビューターはこのドキュメント更新計画とソースコード適用の境界を強制し、ソースファイルに向けられた変更が検証可能な形式で処理されるようにする必要があります。さらに、開発者はdocstring更新の失敗を処理するために特別に設計されたフェーズ認識型の例外型を使用し、エンドツーエンドのライフサイクルの信頼性と保守性を維持する必要があります。

## Public API

- Docstring コンテキスト分析 - docstring 更新の基盤となる、ソースファイル、宣言、既存ドキュメントの構造化表現を構築します。
- 更新およびマージのプランニング - docstring のセクションやシンボルに対する細粒度の追加、削除、置換、およびセマンティックマージを計画し、実行します。
- Docstring レンダリング - docstring のコンポーネント、タグ、フォーマットされた行を有効なドキュメント文字列にレンダリングします。
- 検証と品質管理 - 外部のフォーマットツールやリンターを使用して、docstring の更新プラン、シグネチャ、および結果のソースコードの整合性を検証します。
- エラー処理 - docstring 更新操作に特化したカスタム例外の定義とフェーズ追跡を提供します。
