# Gyomu Facts

[US English](README.md) | JP 日本語

## 概要

このパッケージは、プロジェクトの事実と設定データを構造化し、上位レイヤーのプロセス全体で開発コンテキストを取得および参照するための、型安全で一貫した基盤を提供します。 

パッケージ情報をコンパイルするためのコア分析機能と、コードベースの重要度を評価するためのディレクトリランキング機構を提供します。構造上の詳細を均一な事実として扱うことで、システムがプロジェクトのコンテキストを継続的に活用し、ディレクトリの関連性を評価できるようにします。

## アーキテクチャ

gyomu-facts パッケージは、ソフトウェアプロジェクトを評価するために設計されたコア分析構造を中心に構成されています。責務は、パッケージ分析、ディレクトリランキング、およびターゲット選定を処理するコンポーネントに分割されています。パッケージのルートがメインの分析ルーチンを調整し、パッケージ構造を表す包括的なファクトサマリーをコンパイルします。

この構造内では、特殊なモジュールがスコアリングおよびランキングアルゴリズムを実装しています。これらのコンポーネントは、構造的な重要性に基づいてディレクトリを評価し、スコア計算結果を広範なパッケージ分析ルーチンに直接フィードします。同時に、柔軟な選定オプションによってコードベースの特定の領域をフィルタリングしてターゲットにし、ランキングロジックと連携してコードベースの重要性を評価します。

## インストール

uv を使用してインストールします。

```bash
uv add gyomu-facts
```

## 依存関係

このパッケージは、動作するためにいくつかのランタイム依存関係を使用します。`returns` パッケージは、Success、Failure、Result を使用した成功および失敗の明示的な表現のために使用されます。さらに、`gyomu-schema` はスキーマと共通型の格納場所として機能し、`gyomu-infra` は入出力などの一般的な基盤プロセスを処理し、`gyomu-python-analysis` は Python の分析に使用されます。

## 開発

プロジェクトやパッケージのファクトに対して型安全で一貫性のある基盤を提供するという中核的な目的を達成するため、コントリビューターはファクトの定義をその取得メカニズムから厳密に分離しなければならない。ファクトモデルは、コンシューマー側での暗黙的な型変換を避け、宣言的かつ厳密な型安全性をもって定義する必要がある。ファクトの定義方法と取得方法を分離することにより、このアーキテクチャでは、コンシューミングコードがデータ取得の実装詳細に依存しないことが保証される。さらに、既存のファクトコンシューマーに対する不要な変更を必要とせずに新しい種類のファクトがシームレスに統合できるように設計する必要があり、一貫したアクセスパターンを維持するために、関連するファクトを型安全なコレクションにグループ化しなければならない。

内部アーキテクチャでは、ソースコードおよび設定データの構造解析と、その後の評価プロセスとの間に明確な境界が強制される。具体的には、Package Analysisはプロジェクトソースから検証可能なファクトを構造化することのみを担当し、Directory Rankingは定義されたスコアリング基準に厳密に基づいてディレクトリの重要度の評価を処理する。コントリビューターはこの関心の分離を維持し、ファクトの取得が、それを利用する上位レベルの分析および意思決定ロジックから完全に隔離された状態を保つようにしなければならない。

## Public API

- パッケージ分析 - パッケージ構造を表す包括的なファクト要約とデータモデルをコンパイルします。
- ディレクトリランキング - 構造上の重要度と設定可能な基準に基づいてディレクトリを評価し、スコア付けします。
- ディレクトリ選択 - 関連する対象ディレクトリをフィルタリングして選択するための柔軟な戦略を設定します。
