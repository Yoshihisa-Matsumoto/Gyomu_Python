# Gyomu Facts

[US English](README.md) | JP 日本語

## 概要

gyomu-facts パッケージは、プロジェクトの事実情報を型安全かつ一貫した方法で構造化、取得、参照するための基礎インフラを提供します。その主な目的は、共通のフレームワークを通じてプロジェクトの構造、設定、および関連する事実をモデル化し、アプリケーションが開発コンテキストを把握できるようにすることです。

事実の定義や取得ロジックを利用側コードから分離することで、データソースの基盤となる変更からユーザーを保護します。パッケージの事実をコンパイルして重要度スコアを算出するコア分析およびディレクトリランキング機能を提供し、最終的に自動化されたアーキテクチャ評価と再利用可能な開発コンテキストの管理をサポートします。

## アーキテクチャ

gyomu-facts パッケージは、パッケージ分析とディレクトリのランキングという 2 つの主要なアーキテクチャ機能を中心に構成されています。構造的なパッケージメタデータの収集と、評価およびスコアリングのプロセスを分離するため、責任が明確に分割されています。

組織レベルでは、コードベースは `src/gyomu_facts` をルートとする集約されたモジュール構造を採用しており、特殊なロジックは `src/gyomu_facts/package` ディレクトリ内に分離されています。これらのコンポーネントが直接連携して、自動化されたアーキテクチャ評価をサポートします。具体的には、コアのパッケージ分析ルーチンが、ディレクトリの選択オプションとスコア計算処理を利用して、定義された重要度の基準に基づいてディレクトリを評価し、ランキング付けします。

## インストール

uv を使用してインストールします。

```bash
uv add gyomu-facts
```

## 依存関係

このパッケージは、動作するためにいくつかのランタイム依存関係を使用します。Success、Failure、Resultを通じた成功と失敗の明示的な表現のために `returns` ライブラリを使用しています。さらに、スキーマと共通型のために `gyomu-schema`、I/Oなどの一般的なインフラストラクチャ処理のために `gyomu-infra`、Pythonの分析タスクのために `gyomu-python-analysis` を統合しています。

## 開発

コントリューターは、コンシューマーが実装詳細から切り離された状態を維持できるよう、Factの定義とその取得メカニズムを厳密に分離する必要があります。このアーキテクチャでは、Factの取得プロセスに依存性注入を採用しており、コンシューマーが具体的な実装に直接依存することを防ぎます。さらに、新しい種類のFactを導入する際にも既存のFactコンシューマー側で不要な変更が発生しないようモデルを設計し、パッケージの進化に伴う拡張性を維持する必要があります。

すべてのFactモデルは、宣言的かつ厳密に型安全な方法で定義されなければならず、コンシューマー側での暗黙的な型変換は避ける必要があります。関連するFactは型安全なコレクションにグループ化し、アプリケーション全体で一貫した処理を行えるようにする必要があります。コントリューターは、Factの実装がソースコードやプロジェクト設定から取得可能な事実を厳密に表すようにしなければならず、分析、判断、派生処理などは、Factの定義および取得レイヤーのスコープから完全に除外する必要があります。

## Public API

- パッケージ分析 - パッケージ構造を解析し、包括的なパッケージメタデータとファクトをコンパイルします。
- ディレクトリランキング - 設定可能な選択基準を使用してスコアを計算し、ディレクトリをランク付けします。
