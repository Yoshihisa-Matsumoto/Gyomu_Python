# Gyomu CLI

[US English](README.md) | JP 日本語

## 概要

このパッケージは、Gyomuスイートの主要なコマンドラインインターフェイスのエントリポイントとして機能します。ユーザーからのコマンド、引数、オプションを受け取り、ワークフローなどのコアアプリケーション機能を呼び出すために必要な入力情報を構築する実行インターフェイスを提供します。

コマンドラインの入力処理とアプリケーションロジックを分離することにより、Gyomuの機能が一貫したインターフェイスを通じて確実に利用できるようにします。さまざまな内部ドメインパッケージ間の連携を調整し、ユーザー向け機能をスムーズかつ効果的に公開します。

## アーキテクチャ

gyomu-cli パッケージは、Gyomu スイートのユーザーインタラクションを調整する中央のコマンドラインインターフェイスのエントリポイントを中心に構成されています。Typer を使用して構築されており、挨拶、Google ルーティングの設定、AI の設定、コードスナップショットなどのユーザー向けコマンドを提供します。

責務は、インターフェイス管理とシステム統合に分割されています。コアのソースディレクトリには、コマンドラインの実行フローと基盤となるワークスペースシステムを連携させるプライマリアプリケーションインスタンスが格納されています。パッケージ自体にはドメインロジックは含まれておらず、スキーマ定義、インフラストラクチャサービス、AI モデル、コンパイラ、ワークフロー自動化サービスなどの内部の gyomu ドメインコンポーネントにコマンドを委譲するブリッジとして機能し、複雑な処理をシームレスに実行します。

## インストール

uv を使用してインストールします。

```bash
uv add gyomu-cli
```

## 依存関係

このパッケージは、動作のためにいくつかのランタイム依存関係を利用します。スキーマ定義、データ検証、およびシリアライゼーションやデシリアライゼーションには pydantic を使用します。gyomu-schema はスキーマおよび共通型のレポジトリとして機能し、gyomu-infra は I/O などの一般的なインフラストラクチャ処理を担当します。さらに、LLM の初期化とルーティングテーブルの構築には gyomu-ai を使用し、ルーティングテーブル ID の取得には gyomu-ai-compiler を使用し、スナップショット関連のタスクの実装には gyomu-workflow を使用します。

## 開発

貢献者は、コマンドライン入力の処理を背後にあるドメインロジックから厳密に分離しなければなりません。このパッケージは、ユーザー向けのエントリポイントおよびComposition Rootとして機能し、コマンド、引数、オプションの受け取り、境界での入力検証の実行、型安全な入力の構築のみを担当します。貢献者は、このパッケージ内に個別のアプリケーション処理、ワークフロー制御、またはAIモデルの選択、リトライ、ルーティングの詳細を実装してはなりません。その代わりに、すべての実行リクエストは、定義された公開インターフェースのみを介して、背後にあるドメインロジック、AI設定、およびワークフローサービスに配線されなければならず、これにより、CLI固有の関心事が下位のパッケージに漏洩しないことが保証されます。

予測不可能な操作や暗黙的な設定を避けるため、すべてのコマンド、引数、オプションは、明確性と一貫した動作を持つように設計されなければなりません。貢献者は、必要な依存関係を渡すためにコンストラクタインジェクションや関連するパターンを活用し、実行ターゲットとオプションを明示的に処理することが求められます。さらに、貢献者は、パッケージが処理結果とエラーを適切に区別し、ワークフローの順序付けや再実行ロジックの責任を負うことなく、ユーザーに必要な情報を提示しつつ適切な終了ステータスを返すことを確認しなければなりません。

## Public API

- Command Line Interface - コアとなる gyomu ドメイン機能的操作のためのコマンドライン実行フローを提供します。
- System Integration - スキーマ定義、インフラストラクチャサービス、AIモデル、ワークフロー自動化を含むコアワークスペースシステムを統合します。
