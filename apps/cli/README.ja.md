# Gyomu CLI

[US English](README.md) | JP 日本語

## 概要

このパッケージはTyperを使用して構築された、アプリケーション用の主要なコマンドラインインターフェイスとして機能します。その役割は、ユーザーが端末から直接システム機能にアクセスできるようにする実行インターフェイスを提供することです。

ユーザーからのコマンド、引数、オプションを受け取り、ワークフローなどの下位のアプリケーション機能を呼び出すために必要な入力データを構築します。この設計により、コマンドライン固有の入力処理がコアの処理ロジックから効果的に分離されます。
,
最終的に、実行の調整と必要な設定の統合を行うことで、すべての機能が一貫した統合インターフェイスを通じて利用可能であることを保証します。

## アーキテクチャ

gyomu-cli パッケージは、Typer ベースのコマンドラインインターフェースを中心に構成されており、これがアプリケーションの主要なエントリーポイントとして機能し、ユーザーからのコマンドをオーケストレーションします。責務は、トップレベルのコマンドルーティング、コードスナップショットの実行ワークフロー、およびサービス統合をカバーする個別の機能に分割されています。

コアロジックは `src/gyomu_cli` ディレクトリ内に配置されており、これらの連携するコンポーネントを統合しています。このパッケージは、コードスナップショットのリクエストを処理すると同時に、AI および Google ルーティングサービスの設定を初期化・登録することで、実行フローを調整します。この構成により、コマンドラインインターフェースはユーザー入力とコアのドメインおよびインフラストラクチャパッケージをシームレスに結び付け、実行と統合を管理します。

## インストール

uv を使用してインストールします。

```bash
uv add gyomu-cli
```

## 依存関係

このパッケージは、スキーマ定義、データ検証、シリアライズに pydantic を使用します。コア処理では、共有型として gyomu-schema、I/O およびインフラ処理として gyomu-infra、スナップショット関連のタスクとして gyomu-workflow が必要になります。さらに、LLM の初期化とルーティングテーブルの構築には gyomu-ai が使用され、ルーティングテーブル ID の取得には gyomu-ai-compiler が必要です。

## 開発

コントリューターは、コマンドラインの入力処理とアプリケーションのビジネスロジックを明確に分離することを厳格に維持する必要があります。CLIインターフェースは、コマンド、引数、オプションの受信と解釈、境界での入力バリデーションの実行、および型安全な入力の構築に限定されます。コントリューターは、CLIレイヤー内で個別のアプリケーション処理ロジック、ワークフロー制御、または実行ルーティングを実装することを禁止されています。ワークフローオーケストレーション、実行ターゲット、実行オプション、およびAIモデルの設定（選択、実行、リトライ、ルーティングのメカニズムを含む）はすべて、内部実装への直接的な依存を避け、定義された公開インターフェースを通じて指定された下位パッケージに完全に委譲されなければなりません。

依存関係の管理はComposition Rootパターンに従う必要があり、必要な依存関係が明示的に構築され、コンストラクタインジェクションなどのメカニズムを介して渡されることを保証します。コントリューターは、暗黙的な設定や予測不可能な動作を防ぐために、実行オプションとターゲットが明示的に扱われるようにする必要があります。さらに、コマンドラインの引数とオプションは、直感的で一貫性のある命名規則と予測可能な動作を持つように設計される必要があります。一方で、処理結果とエラーは明確に区別され、CLI固有の関心事を下位パッケージに漏らすことなく、ユーザーに必要な情報を提示し、適切な終了ステータスを返す必要があります。

## Public API

- Command-Line Interface - アプリケーションのコマンドラインインターフェースのエントリーポイントとトップレベルのコマンドルーティングを定義します。
- Snapshot Execution - コードスナップショットの実行と処理ワークフローを処理します。
- AI and Routing Configuration - GoogleのルーティングおよびAI関連サービスとの統合を設定します。
